Visão Geral do Produto

Nome sugerido: TreinaHub (ou DHO Insights) — Central Única de Inteligência de Treinamentos.

Proposta de valor: - Visão macro (executiva) e micro (individual/operacional) em uma única plataforma. - Prevenção de multas trabalhistas por NRs vencidas ou não realizadas. - Antecipação de necessidades de capacitação via alertas e projeções. - Redução de trabalho manual de planilhas do DHO (importação, cruzamento, relatórios).

1.3 Arquitetura de Implantação (Deployment)

  • Modelo: Cloud-native, containerizado (Docker + Kubernetes ou ECS/Fargate).
  • Ambientes: Dev → Homologação → Produção, com CI/CD (GitHub Actions/Azure DevOps).
  • Alta disponibilidade: Multi-AZ, load balancer, auto-scaling horizontal para os serviços de API e ETL (picos em datas de importação em massa).
  • Backup: Snapshots diários do banco (retenção 90 dias) + backup incremental de certificados no Object Storage.
  • Segurança: WAF, criptografia em trânsito (TLS 1.3) e em repouso (AES-256), segregação de dados sensíveis (CPF mascarado por perfil).

2. Banco de Dados Detalhado

2.1 Modelo Conceitual (Entidades Principais)

  1. colaborador
  2. estrutura_organizacional (estado, regional, unidade/loja, setor, cargo)
  3. treinamento (catálogo)
  4. turma_treinamento (edição/execução de um treinamento)
  5. participacao (colaborador x turma — matrícula do colaborador na edição)
  6. certificado
  7. facilitador
  8. regra_obrigatoriedade (define quais treinamentos são obrigatórios para quais cargos/setores)
  9. reciclagem (ligação treinamento → periodicidade)
  10. alerta / notificacao
  11. usuario_sistema / perfil_acesso
  12. importacao_log
  13. auditoria

2.2 Estratégia de Banco de Dados

  • OLTP (transacional): PostgreSQL 16+ — ACID, particionamento por data para tabelas de grande volume (participacao, auditoria, notificacao).
  • OLAP (analítico): Data Warehouse em modelo estrela (star schema) — pode ser o próprio Postgres com views materializadas inicialmente, evoluindo para ClickHouse/BigQuery/Redshift conforme volume.
  • Cache: Redis para sessões, filas de notificação e cache de dashboards (TTL 15 min).
  • Arquivos: Object Storage (S3/Azure Blob) para certificados (PDF/imagem) e planilhas importadas (auditoria).

2.3 Volumetria Estimada (dimensionamento)

Tabela Estimativa de linhas/ano Observação
colaborador 19.000 (ativos) + histórico de desligados crescimento ~5-10%/ano
treinamento (catálogo) 200-500 baixo crescimento
turma_treinamento 3.000-8.000/ano múltiplas turmas por treinamento
participacao 150.000-300.000/ano 19.000 colaboradores × múltiplos treinamentos
certificado ~ igual à participacao 1 certificado por participação concluída
notificacao/alerta 500.000+/ano alta granularidade (90/60/30 dias por pessoa/treinamento)
auditoria milhões/ano requer particionamento mensal

Isso reforça a necessidade de particionamento de tabelas (por ano/mês) e índices compostos nas colunas de filtro mais usadas (loja_id, regional_id, status, data_vencimento).

3.3 Relacionamentos-Chave

  • 1:N — Unidade → Colaboradores; Treinamento → Turmas; Turma → Participações.
  • N:N resolvida — Colaborador ↔ Treinamento, via participacao (que carrega turma e histórico).
  • Auto-relacionamento — Colaborador → Gestor (hierarquia direta) e Estrutura Organizacional (Estado→Regional→Unidade→Setor) para permitir drill-down no mapa operacional.
  • Regra de obrigatoriedade é a tabela que conecta cargo/setor/unidade a treinamentos exigidos, permitindo calcular "pendências" mesmo sem participação registrada (colaborador nunca fez o treinamento obrigatório para seu cargo).

5. Jornada do Usuário

5.1 Persona: Admin DHO Corporativo

  1. Login (SSO corporativo) → Dashboard Executivo (visão de toda a rede).
  2. Configura regras de obrigatoriedade e reciclagem por cargo/NR.
  3. Importa planilhas em massa (admissões/desligamentos, treinamentos realizados).
  4. Audita ranking de lojas/regionais e identifica gargalos críticos.
  5. Gera relatório consolidado para diretoria e para auditorias trabalhistas (compliance NR).
  6. Gerencia usuários e permissões de acesso.

5.2 Persona: Analista DHO

  1. Login → Dashboard Executivo (mesmo escopo corporativo, sem acesso a configurações administrativas).
  2. Realiza cadastro de treinamentos, turmas e facilitadores.
  3. Importa listas de presença e sobe certificados.
  4. Monitora alertas e dispara lembretes para lojas/regionais.
  5. Gera relatórios operacionais por loja/regional.

5.3 Persona: Gestor Regional

  1. Login → Dashboard filtrado automaticamente pela sua Regional (escopo de dados).
  2. Visualiza ranking das lojas sob sua responsabilidade.
  3. Recebe alertas de vencimento e pendências obrigatórias das suas lojas.
  4. Acessa visão micro de qualquer colaborador da sua regional.
  5. Cobra gerentes de loja via sistema (ação "notificar gerente").

5.4 Persona: Gerente de Loja

  1. Login → Dashboard filtrado apenas pela sua loja.
  2. Visualiza pendências da equipe (quem está com treinamento vencido/pendente).
  3. Agenda ou solicita turma de treinamento/reciclagem.
  4. Acompanha certificados da equipe.
  5. Não acessa dados de outras lojas.

5.5 Persona: Consulta (somente leitura)

  1. Login → Dashboard read-only, sem botões de ação/edição.
  2. Usado por auditoria interna, compliance, ou diretoria que só quer visualizar indicadores.

5.6 Mapa de Jornada (fluxo macro)

Login/SSO → Seleção automática de escopo (por perfil) → Dashboard (macro)
   → Clique em indicador → Drill-down (micro) → Ação (notificar, exportar, editar)
   → Volta ao dashboard ou navega para outro módulo

6. Dashboard Executivo (Detalhamento)

6.1 Objetivo

Visão macro, consolidada, para tomada de decisão estratégica (Diretoria, Admin DHO, Analista DHO).

6.2 Indicadores (KPIs) e Fórmulas

Indicador Fórmula
% Colaboradores Treinados (Colaboradores com todos obrigatórios em dia / Total ativos) × 100
% Aderência por Treinamento (Participações concluídas / Colaboradores elegíveis ao treinamento) × 100
Treinamentos Vencidos Count(participação onde data_vencimento < hoje e sem reciclagem registrada)
Próximos do Vencimento (30/60/90d) Count(data_vencimento entre hoje e hoje+N dias)
Obrigatórios Pendentes Colaboradores elegíveis (via regra_obrigatoriedade) SEM participação concluída
Horas de Treinamento Realizadas Σ(carga_horaria × participações concluídas)
Evolução Mensal/Anual Série temporal de conclusões agrupadas por mês/ano
Ranking de Loja/Regional/Estado % aderência agregada por unidade, ordenado desc/asc

6.3 Filtros Globais (aplicam-se a todos os widgets)

  • Período (data início/fim)
  • Estado, Regional, Loja/Unidade, Setor, Cargo
  • Categoria de treinamento (NR, Obrigatório, Comportamental, Técnico, Operacional)
  • Status (Válido, A vencer, Vencido, Pendente)

6.4 Interatividade

  • Todo gráfico/card é clicável → abre visão micro filtrada.
  • Exportação do dashboard completo em PDF (snapshot) ou dados brutos em Excel.
  • Modo "semáforo" (verde/amarelo/vermelho) em rankings, com thresholds configuráveis (ex.: verde ≥90%, amarelo 70-89%, vermelho <70%).

7. Dashboard Operacional (Mapa)

7.1 Objetivo

Visão geoespacial e hierárquica para identificar rapidamente onde estão os gargalos.

7.2 Camadas de Visualização

  1. Mapa (PE/PB/AL) com marcadores por loja/CD, coloridos por % de aderência.
  2. Treemap ou árvore hierárquica Estado → Regional → Loja → Setor → Cargo, permitindo drill-down por clique (breadcrumb sempre visível).
  3. Heatmap de setor x categoria de treinamento (ex.: qual setor tem mais NRs vencidas).

7.3 Regras de Cálculo de Gargalo

  • Um nó (loja/setor/cargo) é sinalizado como gargalo crítico quando:
  • % aderência a obrigatórios < 70%, OU
  • Existe ≥1 treinamento de NR vencido no recorte, OU
  • Existem colaboradores admitidos há >30 dias sem onboarding concluído.

7.4 Ações Disponíveis no Mapa

  • Ver lista de colaboradores do recorte selecionado.
  • Notificar gestor responsável pelo recorte.
  • Solicitar abertura de nova turma de treinamento para o recorte.

8. Regras de Negócio

8.1 Obrigatoriedade

  • RN01 — Um treinamento é obrigatório para um colaborador quando existe registro em regra_obrigatoriedade que o vincula por cargo, setor, unidade ou todos.
  • RN02 — Colaborador sem participação concluída em treinamento obrigatório aplicável a ele é classificado como "Pendente", mesmo sem nunca ter sido matriculado em turma.
  • RN03 — Treinamentos de NR seguem tabela de referência oficial (ex.: NR-35 trabalho em altura, NR-12 máquinas, NR-33 espaço confinado, NR-20 inflamáveis, NR-06 EPI, NR-17 ergonomia) com periodicidade legal pré-configurada, não editável livremente pelo Analista (apenas Admin DHO, com trilha de auditoria).

8.2 Vencimento e Reciclagem

  • RN04 — data_vencimento = data_conclusao + validade_meses do treinamento.
  • RN05 — Quando exige_reciclagem = true, ao vencer, o colaborador some do grupo "válido" e entra automaticamente no grupo "pendente de reciclagem" (não é uma pendência nova, é tratada com rótulo específico para diferenciar de quem nunca fez).
  • RN06 — Alertas são disparados automaticamente em D-90, D-60, D-30 antes do vencimento, e novamente na data do vencimento e a cada 15 dias em atraso (configurável).

8.3 Situação do Colaborador

  • RN07 — Colaboradores com situação "Desligado" saem dos indicadores de aderência ativa, mas seu histórico é preservado para fins de auditoria (retenção mínima conforme política de compliance/LGPD).
  • RN08 — Colaboradores "Afastados" (licença/atestado) são excluídos do denominador de cálculo de aderência durante o período de afastamento, evitando distorção do indicador.
  • RN09 — Colaborador recém-admitido tem prazo de carência (parametrizável, ex.: 30 dias) antes de entrar como "pendente" no onboarding obrigatório.

8.4 Importação

  • RN10 — Toda importação passa por validação: CPF válido, matrícula única, cargo/setor/unidade existentes na base (ou criação assistida), datas coerentes (conclusão ≤ hoje).
  • RN11 — Registros duplicados (mesmo colaborador + mesmo treinamento + mesma data) são identificados e não geram duplicidade de participação.
  • RN12 — Toda importação gera log em importacao_log, rastreável e reversível (rollback) por até 24h.

8.5 Permissões e Escopo de Dados

  • RN13 — Gestor Regional e Gerente de Loja só visualizam dados do seu próprio escopo hierárquico (aplicado via filtro obrigatório na camada de API, nunca apenas no front-end).
  • RN14 — Perfil "Consulta" nunca tem acesso a ações de escrita (CRUD bloqueado em nível de API).
  • RN15 — CPF é armazenado criptografado e exibido mascarado, exceto para Admin DHO Corporativo (com log de auditoria de quem visualizou o dado completo).

8.6 Certificados

  • RN16 — Certificado só é gerado/vinculado quando status = Concluído e frequencia_pct ≥ mínimo exigido (parametrizável, padrão 75%).
  • RN17 — Certificados possuem hash de validação para evitar fraude/adulteração (auditoria trabalhista).

9. Fluxo de Importação de Planilhas

9.1 Fluxo Geral (ETL)

1. Usuário baixa TEMPLATE padrão (.xlsx) por tipo de entidade
        ↓
2. Preenche/exporta do sistema de origem (ERP/folha) e faz upload
        ↓
3. Parser lê o arquivo (biblioteca: openpyxl/pandas no backend)
        ↓
4. VALIDAÇÃO em 3 níveis:
   a) Estrutural — colunas obrigatórias presentes, tipos corretos
   b) Referencial — cargo/setor/unidade/treinamento existem na base
   c) Negócio — CPF válido, datas coerentes, duplicidade
        ↓
5. PRÉ-VISUALIZAÇÃO — mostra linhas válidas x com erro (editável inline)
        ↓
6. Usuário corrige erros na tela ou reenvia planilha corrigida
        ↓
7. CONFIRMAÇÃO — processamento em fila assíncrona (para grandes volumes)
        ↓
8. Gravação em banco (transação em lote/batch, com rollback em caso de falha)
        ↓
9. Log de importação + notificação ao usuário (sucesso/erro) por e-mail/sistema
        ↓
10. Disparo automático do recálculo de indicadores (dashboards) e alertas

9.2 Templates de Importação (colunas obrigatórias)

Template — Colaboradores matricula | nome | cpf | cargo | setor | unidade | regional | estado | gestor_matricula | data_admissao | situacao

Template — Treinamentos (catálogo) nome_treinamento | categoria | carga_horaria | tipo | obrigatorio(S/N) | norma_nr | validade_meses | exige_reciclagem(S/N)

Template — Participações/Presença matricula | nome_treinamento | data_realizacao | facilitador | local | status | frequencia_pct | nota

Template — Certificados matricula | nome_treinamento | data_conclusao | numero_certificado | arquivo (link/anexo)

9.3 Tratamento de Erros Comuns

Erro Ação do Sistema
CPF inválido/faltante Bloqueia linha, sinaliza para correção
Matrícula não encontrada Sugere criação de novo colaborador ou correção de matrícula
Treinamento não cadastrado Sugere cadastro automático do treinamento (fluxo assistido)
Data de conclusão futura Bloqueia linha (inconsistência)
Linha duplicada Ignora e sinaliza como "já existente", sem duplicar

9.4 Importação Recorrente / Automática (Integrações)

  • Job agendado (noturno) para sincronizar admissões/desligamentos direto do ERP/Folha via API ou arquivo SFTP, eliminando dependência de upload manual para dados cadastrais.
  • Webhook de LMS/EAD externo para importar conclusões de treinamentos online automaticamente.

11. Estrutura de APIs

11.1 Padrão

  • REST (com opção de GraphQL para telas de dashboard com queries complexas/variáveis).

12. Modelo SaaS Escalável

12.1 Arquitetura Multi-Tenant (mesmo operando hoje como single-tenant)

Ainda que o uso inicial seja para uma única rede de varejo, recomenda-se desenhar desde já como SaaS multi-tenant, permitindo: - Replicar a plataforma para outras empresas do grupo/franquias no futuro. - Isolamento lógico de dados por tenant_id em todas as tabelas (mesmo com 1 único tenant ativo hoje). - Configurações (regras de obrigatoriedade, thresholds de alerta, cores/branding) parametrizáveis por tenant.

12.2 Estratégia de Isolamento

  • Fase 1 (atual): Single-tenant lógico — tenant_id fixo, banco único.
  • Fase 2 (expansão): Multi-tenant com schema compartilhado (tenant_id em todas as queries) — mais barato e fácil de manter.
  • Fase 3 (grande escala): Multi-tenant com banco/schema dedicado por cliente maior, para isolamento total e customizações profundas.

12.3 Modelo de Cobrança (caso vire produto comercial)

Plano Público-alvo Escopo
Starter Redes pequenas (<2.000 colaboradores) Dashboard básico, sem mapa operacional
Professional Médio porte (2.000-20.000) Módulo completo (como especificado aqui)
Enterprise Grandes redes/múltiplas empresas Multi-tenant, API aberta, BI avançado, SLA dedicado

12.4 Escalabilidade Técnica

  • Auto-scaling horizontal dos serviços de API e processamento de importação (picos sazonais: admissões em massa, campanhas de NR).
  • Filas assíncronas para não travar a experiência do usuário durante importações grandes.
  • CDN para assets estáticos e cache de dashboards (dados que mudam 1x/dia podem ser cacheados agressivamente).
  • Separação clara entre carga transacional (OLTP) e carga analítica (OLAP/DW), evitando que relatórios pesados impactem o cadastro do dia a dia.

13. Protótipo Visual / Design System

13.1 Referências de Estilo

Inspiração em Power BI, Tableau e sistemas corporativos de RH (Gupy, TOTVS RH, SAP SuccessFactors): visual clean, denso em dados mas organizado, paleta corporativa com uso de cor apenas para semântica (status/urgência).

13.2 Paleta de Cores Sugerida

Uso Cor
Primária (marca) Azul corporativo #1A3C6E
Secundária Cinza-azulado #4A5568
Sucesso / Em dia Verde #22A559
Atenção / A vencer Amarelo/Laranja #F5A623
Crítico / Vencido Vermelho #E5484D
Fundo Branco/Cinza claro #F7F8FA
Texto Cinza escuro #1F2933

13.3 Tipografia

  • Fonte: Inter ou Roboto (legibilidade em dashboards densos).
  • Hierarquia: Título 24px/bold, Subtítulo 16px/semibold, Corpo 14px/regular, Labels 12px/medium.

13.4 Componentes-Chave do Design System

  • Cards de KPI com número grande + variação percentual (↑/↓) vs período anterior.
  • Semáforo (badge colorido) reutilizado em toda a plataforma para status de treinamento.
  • Breadcrumb hierárquico (Estado ▸ Regional ▸ Loja ▸ Setor ▸ Cargo) fixo no mapa operacional.
  • Tabelas densas com ordenação/filtro inline e exportação rápida (ícone Excel/PDF no canto).
  • Drawer lateral (painel deslizante) para drill-down sem sair da tela atual — preserva contexto do usuário.
  • Filtros globais persistentes no topo, aplicáveis a toda a sessão até serem limpos.

13.5 Acessibilidade e Responsividade

  • Contraste mínimo AA (WCAG 2.1) — importante pois cores carregam significado (semáforo), então sempre acompanhar cor + ícone/texto (não depender só da cor).
  • Layout responsivo: menu lateral colapsa em ícones no tablet; em mobile, prioriza-se dashboard resumido e ações de gestor de loja (consulta rápida de pendências da equipe).
